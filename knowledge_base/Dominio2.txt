Proceso de entrenamiento y ajuste fino de los modelos fundacionales 
¿Cuáles son los elementos clave del entrenamiento de un modelo fundacional? Son el entrenamiento previo, el ajuste fino y el entrenamiento previo continuo. Empecemos con el entrenamiento previo, el cual es un proceso complejo. Requiere millones de unidades de procesamiento gráfico (GPU) y horas de computación. Terabytes y petabytes de datos, billones de tokens, prueba y error, y tiempo. Durante el entrenamiento previo, los modelos de IA generativa aprenden sus habilidades. ¿En qué se diferencian el entrenamiento previo y el ajuste fino? En el entrenamiento previo, el LLM aprende de enormes cantidades de datos no estructurados y con un aprendizaje autosupervisado.
Aunque los modelos fundacionales se hayan entrenado con millones de documentos, videos, imágenes, archivos, audios y más, y hayan aprendido los aspectos básicos del lenguaje humano, es posible que necesiten un entrenamiento o instrucciones adicionales para su dominio y conjunto de datos. O bien, es posible que deban aprender a realizar tareas de los seres humanos y a razonar. El ajuste fino es un proceso que amplía el entrenamiento del modelo a fin de mejorar la generación de respuestas para una tarea específica. Es un proceso de aprendizaje supervisado en el que se utiliza un conjunto de datos de ejemplos etiquetados para actualizar las ponderaciones del LLM. 


El ajuste de fino adapta los modelos fundacionales a sus conjuntos de datos y casos prácticos personalizados. El ajuste fino basado en instrucciones usa ejemplos etiquetados para mejorar el rendimiento en tareas específicas. Los LLM pueden realizar muchas tareas diferentes en un solo modelo. Sin embargo, ¿qué sucede si la aplicación necesita realizar una sola tarea? Puede ajustar un modelo previamente entrenado para mejorar su rendimiento en las tareas específicas de sus casos prácticos. Sin embargo, ajustar una sola tarea puede tener una limitación, que es el olvido catastrófico. El olvido catastrófico ocurre cuando todo el proceso de ajuste fino modifica las ponderaciones del LLM original. Esto puede mejorar el rendimiento del ajuste fino de una sola tarea, pero puede disminuir el de otras. Otro aspecto que debe considerar es si el olvido catastrófico afectará su caso práctico. Si necesita un rendimiento fiable en una sola tarea, es posible que no le preocupe que el modelo no pueda generalizarse en otras tareas.
Durante el ajuste fino completo, cada parámetro del modelo se actualiza mediante el aprendizaje supervisado, pero existen métodos eficientes para adaptar los parámetros del modelo. Cuando entrena y ajusta un modelo fundacional, se cargan los parámetros del modelo y se agrega memoria para el optimizador, los gradientes, las activaciones directas y la memoria temporal. Estos componentes pueden agregar bytes de memoria de GPU para cada parámetro del modelo y aumentar los costos de computación del proceso de ajuste fino. 



El ajuste fino con parámetros eficientes (PEFT) es un proceso y un conjunto de técnicas que congelan o conservan los parámetros y las ponderaciones del LLM original, y ajustan o entrenan una pequeña cantidad de capas y parámetros de adaptadores específicos para cada tarea. El PEFT reduce la computación y la memoria necesarias, ya que ajusta un pequeño conjunto de parámetros del modelo. La adaptación de rango bajo (LoRA) es una técnica popular del PEFT que también conserva o congela las ponderaciones originales del modelo fundacional y crea nuevas matrices de rango bajo que se pueden entrenar en cada capa de una arquitectura de transformadores. El PEFT y la LoRA modifican las ponderaciones del modelo, pero no las representaciones.
Las representaciones codifican la información semántica, de forma similar a las incrustaciones. El ajuste fino de representación (ReFT) es un proceso de ajuste fino que congela el modelo básico y aprende las intervenciones específicas de cada tarea en las representaciones ocultas. La hipótesis de la representación lineal establece que los conceptos se codifican en subespacios lineales de representación en una red neuronal. El ajuste fino de multitareas es una extensión del de una sola tarea. El ajuste fino de multitareas requiere una gran cantidad de datos. Para ello, el conjunto de datos de entrenamiento tiene ejemplos de entradas y salidas para varias tareas. En concreto, el conjunto de datos puede contener ejemplos que le indiquen a un modelo que complete varias tareas, como revisiones o calificaciones, resúmenes, traducciones de código, etc. Esto produce un modelo ajustado a las instrucciones que aprendió a completar muchas tareas diferentes en simultáneo. Además, puede calcular las pérdidas a partir de los ejemplos para actualizar sus ponderaciones. Esto ayuda a mitigar y evitar el olvido catastrófico. Una pregunta:
¿qué proceso de ajuste fino modifica las ponderaciones del modelo para adaptarse a los datos específicos del dominio? El ajuste fino mediante la adaptación de dominios permite usar modelos fundacionales preentrenados y adaptarlos a tareas específicas con datos limitados específicos del dominio. Este tipo de ajuste puede usarse para que el modelo funcione con el lenguaje específico del dominio, como la jerga del sector, los términos técnicos u otros datos especializados. Amazon SageMaker JumpStart ofrece la capacidad de ajustar un modelo de lenguaje de gran tamaño, sobre todo uno de generación de texto en el conjunto de datos específico del dominio. Los modelos se pueden ajustar con su conjunto de datos personalizado para mejorar el rendimiento en determinados dominios. También se puede usar el ajuste fino del aprendizaje por refuerzo a partir de retroalimentación humana (RLHF). De esta forma, puede mejorar el rendimiento del modelo y hacer que comprenda mejor las peticiones similares a las que redactan las personas para generar respuestas del mismo estilo. El RLHF utiliza el aprendizaje por refuerzo para ajustar el LLM con datos de retroalimentación humana a fin de alinear mejor el modelo a las preferencias humanas.



Entrenamiento previo, el ajuste fino y el entrenamiento previo continuo
Centrémonos en la preparación de los datos para ajustar con precisión el modelo fundacional. El primer paso consiste en preparar los datos de entrenamiento. Se han utilizado muchos conjuntos de datos y bibliotecas de plantillas de peticiones públicos para entrenar modelos de lenguaje de gran tamaño. Las bibliotecas de plantillas de peticiones incluyen muchas plantillas para diferentes tareas y conjuntos de datos. Cuando esté listo el conjunto de datos de instrucciones, puede dividirlo en particiones de entrenamiento, validación y prueba. Durante el ajuste fino, elige las peticiones del conjunto de datos de entrenamiento y las pasa al LLM para que genere las respuestas. Luego, compara la distribución de las respuestas y las etiquetas de entrenamiento para calcular una pérdida entre las dos distribuciones de tokens. Puede usar la pérdida calculada para actualizar las ponderaciones del modelo.
Después de muchos lotes de pares de peticiones completadas, actualice las ponderaciones a fin de mejorar el rendimiento del modelo para esa tarea. Como en el aprendizaje supervisado estándar, puede definir pasos de evaluación independientes para medir el rendimiento del LLM con el conjunto de datos de validación de retención. Obtendrá la exactitud de validación y, luego de completar el ajuste fino, podrá realizar una evaluación final del rendimiento con el conjunto de datos de prueba de retención. Este último resultado indicará la exactitud de la prueba. 

¿Cómo puede preparar los datos para el proceso de ajuste fino en AWS? Hagamos una pausa para hablar de los aspectos básicos de la preparación de datos. En el machine learning, la preparación de datos consiste en recopilar, preprocesar y organizar los datos sin procesar para el modelo. Agregué tarjetas didácticas para verlo en detalle, pero por ahora, repasemos rápido algunas opciones de preparación de datos en AWS.
Si tiene una preparación de datos con poco código, puede usar Amazon SageMaker Canvas para crear flujos de datos que definan el preprocesamiento de datos del ML. Estos flujos de datos incluyen flujos de trabajo de ingeniería que utilizan poco o nada de código. Si necesita escalar la preparación de datos, puede usar marcos de trabajo de código abierto como Apache Spark, Apache Hive o Presto. Amazon SageMaker Studio Classic ofrece integración en Amazon EMR. Además, si no necesita servidores, puede usar el motor sin servidor de Apache Spark de las sesiones interactivas de AWS Glue. Estas agregarán, transformarán y prepararán datos de varias fuentes en SageMaker Studio Classic.
Si necesita usar un lenguaje de consulta estructurada (SQL) en SageMaker Studio para preparar los datos, puede usar el Jupyter Lab. Si la preparación de datos está destinada a la detección y el almacenamiento de características, puede usar el Almacén de características de Amazon SageMaker a fin de buscar, descubrir y recuperar características para el entrenamiento de modelos. También puede usarlo a fin de proveer un repositorio centralizado para almacenar datos de características en un formato estandarizado. Supongamos que en la preparación debe deben detectar sesgos de los datos. Puede usar Amazon SageMaker Clarify para analizarlos y detectar posibles sesgos en varias facetas. Por ejemplo, SageMaker Clarify puede detectar si los datos de entrenamiento contienen representaciones desequilibradas o sesgos de etiquetado entre grupos, como el género, la raza o la edad. Si tiene datos que deben etiquetarse, use SageMaker Ground Truth para administrar los flujos de trabajo de etiquetado de datos de los conjuntos de datos de entrenamiento.



El entrenamiento previo continuo también es importante para la IA generativa por varios motivos. El resultado de los modelos de IA generativa es no determinista, lo que dificulta la validación.
Es importante elegir métricas, puntos de referencia y conjuntos de datos que ayuden a evaluar las capacidades de los modelos y garantizar que no generen resultados dañinos. Cuando preentrena modelos continuamente con datos de diferentes temas, géneros y contextos, con el tiempo, los modelos se vuelven más potentes. Aprenden a utilizar mejor los datos fuera del dominio acumulando más conocimiento y una mayor adaptabilidad. Esta capacidad crea valor para su organización. Por ejemplo, el entrenamiento previo continuo en Amazon Bedrock contribuye al entrenamiento de los FM de Amazon Titan Text Express y Amazon Titan Text Lite. Puede personalizarlos con sus propios datos sin etiquetar en un entorno seguro y administrado.
